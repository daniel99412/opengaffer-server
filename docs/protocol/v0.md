# Protocolo v0

Estado: **borrador**. Es el contrato entre `opengaffer-server` y
`opengaffer-client`. Cualquier cambio incompatible sube `protocol`.

## Transporte

- JSON UTF-8.
- Un mensaje por línea (JSONL) en stdio y, más adelante, un frame de texto por
  WebSocket.
- No hay framing propio: el salto de línea (o el frame) delimita el mensaje.

## Sobre

Todo mensaje tiene exactamente tres campos fijos y un `body` variable:

| campo | tipo | descripción |
|---|---|---|
| `protocol` | entero | versión del protocolo; hoy `0` |
| `id` | ULID | identificador único del mensaje |
| `type` | string | `request`, `command`, `response` o `event` |
| `body` | objeto | contenido; su forma depende de `type` |

```json
{
  "protocol": 0,
  "id": "01JB7Y6Q3M8ZC4R5T9V2K1X0AB",
  "type": "command",
  "body": {}
}
```

El `body` de `request`, `command` y `event` lleva un `name` con notación de
puntos. Los comandos usan imperativo (`clubs.claim`) y los eventos pasado
(`club.claimed`). `response` no lleva `name`: se correlaciona con `reply_to`.

## Tipos

### `request`

Llamada de sistema o previa a la autenticación. No modifica el mundo.

```json
{
  "protocol": 0,
  "id": "01JB7Y6Q3M8ZC4R5T9V2K1X0AB",
  "type": "request",
  "body": {
    "name": "system.ping",
    "args": {}
  }
}
```

### `command`

Intención autenticada que puede modificar el mundo. Es idempotente por
`command_id` y usa concurrencia optimista con `expected_version`.

```json
{
  "protocol": 0,
  "id": "01JB7Y6Q3M8ZC4R5T9V2K1X0AB",
  "type": "command",
  "body": {
    "name": "clubs.claim",
    "session_id": "01JB7Y6Q3M8ZC4R5T9V2K1X0AC",
    "user_id": "01JB7Y6Q3M8ZC4R5T9V2K1X0AD",
    "command_id": "01JB7Y6Q3M8ZC4R5T9V2K1X0AE",
    "expected_version": 42,
    "args": {
      "club_id": "01JB7Y6Q3M8ZC4R5T9V2K1X0AF"
    }
  }
}
```

### `response`

Respuesta a un `request` o `command`.

```json
{
  "protocol": 0,
  "id": "01JB7Y6Q3M8ZC4R5T9V2K1X0AG",
  "type": "response",
  "body": {
    "reply_to": "01JB7Y6Q3M8ZC4R5T9V2K1X0AB",
    "ok": true,
    "result": {
      "club_id": "01JB7Y6Q3M8ZC4R5T9V2K1X0AF"
    }
  }
}
```

Si `ok` es `false`, `result` no existe y `error` es obligatorio:

```json
{
  "protocol": 0,
  "id": "01JB7Y6Q3M8ZC4R5T9V2K1X0AH",
  "type": "response",
  "body": {
    "reply_to": "01JB7Y6Q3M8ZC4R5T9V2K1X0AB",
    "ok": false,
    "error": {
      "code": "conflict",
      "message": "expected version 42, current 43",
      "details": { "current_version": 43 }
    }
  }
}
```

### `event`

Notificación del servidor. Lleva `seq` monotónico para sync y replay.

```json
{
  "protocol": 0,
  "id": "01JB7Y6Q3M8ZC4R5T9V2K1X0AJ",
  "type": "event",
  "body": {
    "name": "club.claimed",
    "seq": 1235,
    "world_id": "01JB7Y6Q3M8ZC4R5T9V2K1X0AK",
    "data": {
      "club_id": "01JB7Y6Q3M8ZC4R5T9V2K1X0AF",
      "user_id": "01JB7Y6Q3M8ZC4R5T9V2K1X0AD"
    }
  }
}
```

## Campos del `body`

### `request`

| campo | tipo | obligatorio |
|---|---|---|
| `name` | string | sí |
| `args` | objeto | no; default `{}` |

### `command`

| campo | tipo | obligatorio |
|---|---|---|
| `name` | string | sí |
| `session_id` | ULID | sí |
| `user_id` | ULID | sí |
| `command_id` | ULID | sí |
| `expected_version` | entero | sí |
| `args` | objeto | no; default `{}` |

### `response`

| campo | tipo | obligatorio |
|---|---|---|
| `reply_to` | ULID | sí |
| `ok` | bool | sí |
| `result` | cualquiera | si `ok` es `true` |
| `error` | objeto | si `ok` es `false` |

`error` tiene `code` y `message` obligatorios, y `details` opcional.

### `event`

| campo | tipo | obligatorio |
|---|---|---|
| `name` | string | sí |
| `seq` | entero | sí |
| `world_id` | ULID | sí |
| `data` | objeto | no; default `{}` |

## Identificadores

- `id`, `session_id`, `user_id`, `command_id`, `world_id`: ULID en string.
- `seq`: entero sin signo asignado por el servidor. No es ULID: necesitas orden
  total y comparación barata para sync.
- El **token de sesión no es `session_id`**. El token es un secreto aleatorio de
  256 bits, se guarda hasheado y viaja solo en el handshake.
- `session_id` y `user_id` en un `command` son contexto para logs y auditoría.
  El servidor los deriva de la conexión autenticada y rechaza si no coinciden.
  Nunca autoriza con lo que manda el cliente.

## Validación

- `protocol` distinto de `0` → error `unsupported_protocol`.
- `type` desconocido → error `invalid_message`.
- `name` desconocido → error `unknown_name`.
- Campos desconocidos en `body` se ignoran (compatibilidad hacia adelante).
- En `response`, `ok=true` no puede traer `error`; `ok=false` exige `error` y no
  admite `result`.
- Un `command_id` repetido en el mismo mundo devuelve la respuesta original sin
  volver a aplicar el comando.
